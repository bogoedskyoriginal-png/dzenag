# Локальное восстановление оплаченного Discovery

Ошибка одного кандидата не требует повторной оплаты всего поискового ответа.
Восстановление доступно на рабочем столе: «Разобраться с ошибкой» →
«Обработать сохранённый Discovery бесплатно». API-ключ для этого действия не нужен.

Действие читает только успешную квитанцию существующего запуска и сохранённый Analytics.
Используются снимки настроек и промптов этого запуска; активные промпты не изменяются.
Перед обработкой SQLite копируется через backup API в `data/backups/`.
AI-клиент и фоновый pipeline не запускаются. Planner требует отдельного действия.

## Что проверяется

- Валидный полный JSON, Discovery 1.0, обязательные поля, версия, run_id и период.
- Каждый кандидат отдельно по неизменённой Pydantic-схеме Idea.
- Уникальность idea_id. При неоднозначном ID исключаются все его экземпляры.
- Ссылки на источники внутри того же кандидата, Analytics и известные статьи.
- Наличие URL источников в поисковых метаданных ответа.
- Подтверждённые основания и состав подборки; статус `needs_validation` автоматически
  не повышается до `ready_for_planning`.

Невалидный кандидат исключается из нормализованного списка с причиной в `rejected_ideas`.
Подробные пути ошибок и неизвестные source_id сохраняются в журнале `DISCOVERY_VALIDATION`.
Оригинальный оплаченный JSON в `ai_calls`, расходы и результат Analytics остаются неизменными.
Источники из других кандидатов не заимствуются; фиктивные источники и новые факты не создаются.

Ошибку верхнего уровня, другой run_id/период, оборванный JSON и `finish_reason=length`
нельзя исправить исключением отдельных кандидатов: такой ответ остаётся заблокированным.

## Где Sonar передаёт поисковые ссылки

Поддерживаются `citations`, `search_results` и
`choices[].message.annotations[].url_citation.url`. Пустые первые два массива не означают,
что поиск отсутствовал: совместимый ответ может содержать ссылки в аннотациях.
Они сохраняются вместе с `choices` и учитываются при проверке источников.

В старых квитанциях приложение подставляло пустые массивы для отсутствующих полей.
По такому сохранённому ответу невозможно установить, отсутствовало ли поле в исходном
HTTP-ответе или API прислал именно пустой массив. Новые квитанции дополнительно сохраняют
`search_metadata.citations_field_present` и `search_metadata.search_results_field_present`.
Старые квитанции не переписываются.

Наличие URL в поисковом ответе подтверждает происхождение ссылки, а не истинность всех
предложений статьи. Полноценный Research по-прежнему необходим после утверждения концепта.

## Недобор идей

Discovery может законно вернуть `partial`. Если пригодных идей меньше числа статей,
результат сохраняется, а Planner блокируется **до платного запроса**. Непроверенные идеи
не подставляются для заполнения слотов. Нельзя создавать несколько концептов из одного
кандидата, чтобы скрыть недобор.

Пользователь должен отдельно решить вопрос дополнительного поиска/проверки идей либо
согласовать другой объём плана. Восстановление не меняет целевой объём существующего запуска.
Если идей достаточно, запуск получает статус `DISCOVERY_READY` и ждёт отдельного запуска Planner.
