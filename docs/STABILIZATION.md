# Исполнение автономной подготовки

## Границы и совместимость

Используются существующие SQLite, Pipeline, фоновый worker и Playwright-профиль.
Новый основной интерфейс содержит четыре раздела и шесть пользовательских этапов.
Прежний интерфейс доступен через `/?view=legacy`; старые ручные запуски не получают
разрешение на автоматическое утверждение или дополнительные расходы задним числом.
Финальная публикация не входит в автономную подготовку черновиков.

Аддитивная миграция 6 сохраняет старые таблицы. Перед миграцией создаётся резервная
копия SQLite. Новые таблицы: `prompt_contracts`, `run_authorizations`,
`call_reservations`, `plan_approvals`, `response_repairs`.

## Причины прежних остановок и исправления

| Причина | Изменение |
| --- | --- |
| Буквальное сравнение evidence anchor с сырым Markdown | Нормализация видимого текста, Unicode и типографики; сохраняются номера блоков и хеши. Разные числа, имена и отрицания не приравниваются. |
| Ссылка на год через «того же года» | Разрешается только единственный явно названный предшествующий год в том же абзаце. Исходный текст и квитанция не переписываются. |
| Версия схемы зависела от формулировки промпта | Явные метаданные версии и схемы отдельно от текста и истории промптов. |
| Неверный `writing_mode` | В Writer передаются `from_scratch` / `rewrite_draft`. |
| Структурное исправление повторяло поиск, теряло уже оплаченные источники | В исправление передаются предыдущий ответ и проверенные URL из квитанций; для преобразования JSON веб-инструменты отключаются. |
| Модель объявляла вычисленные показатели без определения метрик | Числовая воронка Analytics берётся из проверенной сводки Python; неизвестные величины остаются null, ограничения сохраняются. |
| Одна статья задерживала всю неделю | После плана каждая статья проходит Research → Writer → Image → QA независимо. |
| Неподтверждённый тезис исследовался снова без изменения | Ограниченная замена резервной идеей или новая редакция только на основании уже подтверждённых фактов; повторная проверка и программное утверждение плана. |
| План требовал обязательного нажатия «Утвердить» | Проверка календаря, источников, заданий и повторов; утверждение оркестратором только по сохранённому разрешению пользователя. |
| Отсутствие фото блокировало чтение статьи | Явный частичный результат и предупреждение; проверки текста, фактов и включённых изображений сохраняются. |
| Подбор фото ограничивался логотипом и первыми ссылками | Извлечение реальных URL из подтверждённых HTML-страниц, распределение кандидатов между страницами, учёт подписей источника; отдельная визуальная проверка реальных скачанных файлов. |
| Правило подборки применялось к любой статье | После блока режиссёра/актёров изображения ставятся в подборках; другие форматы используют существующие абзацы и заголовки. |
| Будущая обложка считалась уже скачанным asset | Python создаёт обложку и вставляет её один раз. Настоящий источник обложки и ссылки на внутренние фото остаются обязательными. |
| Повторная проверка черновика зависала на поиске в Студии | Сначала проверяется единственная точная строка материала; адрес редактора читается из её фактической ссылки. |

## Общий приём ответа и восстановление

1. Provider сохраняет исходную квитанцию и расходы до Pydantic-валидации.
2. `execution.py` обрабатывает JSON-обёртки, однозначные enum и поля, которыми
   управляет приложение. Ссылки Research проверяются с подробными путями;
   дубли идентификаторов не разрешаются произвольным выбором источника.
3. При нормализации хранится журнал отличий; оплаченные ответы неизменны.
4. `perform` применяет общий предел исправлений для стадий и отдельных статей.
   Новый ответ получает стабильный ключ `:repair:N` и ссылается на предыдущую квитанцию.
5. Неопределённое списание, timeout и неизвестный исход не порождают слепой повтор.
   Локальный `replay_stage` использует provider только для чтения квитанций;
   он не может вызвать HTTP или запустить следующие стадии.

Смысловая достаточность Research проверяется отдельно от корректности JSON.
Подтверждённый частичный Research сохраняется, но не превращается в разрешение Writer.
Новая редакция концепта не использует досье старой редакции как готовое.

## Разрешения и расходы

Пользователь один раз задаёт дополнительный бюджет конкретного запуска. Ранее
оплаченные результаты учитываются отдельно и переиспользуются бесплатно.
Новые вызовы предварительно резервируют консервативный верхний предел стоимости
по каталогу: контекст модели, максимум ответа, старшие тарифные уровни и ограниченные
инструменты. Веб-поиск ограничен числом использований; месячный лимит действует отдельно.
Без известных цен автономный платный вызов запрещён.
Лимит ответа Planner автоматически увеличивается под размер календаря, если каталог
подтверждает поддержку такого объёма. Поиск фотографий настраивается отдельно от Research,
чтобы Visual с внешним поиском не менял поисковый режим Sonar.

`PENDING`, `UNCERTAIN` и превышение резерва блокируют новые расходы.
Успешная квитанция повторно не оплачивается. После падения worker состояние
восстанавливается только после получения существующей межпроцессной блокировки.
Неиспользованный остаток разрешения не расширяется простым повторным нажатием кнопки.
Разрешение на черновики хранится отдельно; разрешение на публикацию всегда false.

## Календарь и фон

Произвольные даты и суммарно 1–21 статья. Для 1–3 статей в день назначаются
05:00, 06:00, 16:00 по Москве; для большего количества — разные часы.
Сохранённый запуск использует свой снимок календаря и не пересоздаёт даты при возобновлении.
Прошедшие слоты и некорректное количество проверяются до платных операций.
Работа выполняется существующим отдельным процессом и не зависит от открытой вкладки.
Планировщик Windows использует тот же worker и требует отдельного согласия на расходы.

## Статистика и черновики

Автоматическая статистика использует только проверенную кнопку экспорта конкретного
авторизованного профиля. Оригинальный XLSX проходит обычный предпросмотр/нормализацию;
предыдущий импорт не изменяется. Неизвестная дата измерения не заменяется датой анализа.
При недоступности Студии сохраняется работа с пригодным локальным импортом.

Черновик формируется из `assembled_document_ref`: заголовки, абзацы, выделения,
списки и реальные локальные изображения. После сохранения редактор открывается снова.
В SQLite сохраняются адрес, ID, хеш и результат проверки. Сбой после начала создания
без известного URL блокирует повторное создание до сверки, а известный URL используется
для изменения того же материала. Публикационные настройки не открываются.

## Проверки и границы доказанного

Mock E2E проходит настоящий оркестратор для 1, 3, 5 и 21 статьи, частичные ошибки,
восстановление, бюджеты и отсутствие повторной оплаты. Browser E2E запускает отдельный
mock worker кнопкой интерфейса, закрывает вкладку во время работы и проверяет результат
после её открытия. Реальная SQLite не используется как тестовая база.

Успех mock E2E не означает гарантированное качество ответов конкретных моделей.
При живой проверке провайдер может вернуть прозу вместо JSON, недостаточный Research
или неверные ссылки. Это ограниченные восстанавливаемые попытки, а не основание
ослабить фактчекинг. В текущей проверке новый платный запуск не завершил всю цепочку
из-за недостаточного Research. Массовый реальный запуск 21 статьи не подтверждён.
Подробные локальные доказательства и финансовые итоги сохраняются в игнорируемом
каталоге `data/autonomy-audit`, без ключей и браузерных cookies в Git.

Реально восстановлен оплаченный Writer существующего запуска без нового вызова Writer.
Из подтверждённого кадра локально создана обложка 16:9; оформленный текст с обложкой
повторно проверен в одном и том же черновике Студии. Внутренние иллюстрации в этой
реальной статье не размещены и отмечены предупреждением QA. Передача внутренних фото
проверена на локальном mock-редакторе; массовая реальная передача не подтверждена.
Подтверждён настоящий экспорт XLSX из авторизованной Студии и его импорт без изменения
исходной статистики. Публичных публикаций в ходе проверки не было.
