# Восстановление редакционной недели

Discovery 1.0 сохраняет корректных кандидатов независимо от ошибок соседних идей.
Локально исправляются только однозначные представления: одиночный объект вместо
массива, строковый список из одного ID, пробелы и регистр ссылки на единственный
объявленный источник, строковые целочисленные оценки. Отсутствующие факты,
источники и неоднозначные ID не додумываются. Исходные AI-ответы не изменяются.

Если подтверждённых кандидатов достаточно, pipeline сразу вызывает Planner.
Идеи `needs_validation` сохраняются, но не используются как готовые к планированию.
При нехватке рабочий стол предлагает два действия:

- Разрешить ограниченное дозаполнение: указать дополнительный бюджет, максимум
  запросов и резерв на запрос. Согласие сохраняется для запуска и версии Analytics.
  Каждый запрос получает недостающее количество, найденные и исключённые темы.
  Каждый пакет архивируется отдельно; объединение с накопленным результатом
  выполняется атомарно. Совпадающие ID разных пакетов получают уникальные суффиксы;
  локальные ID источников остаются в пределах своей идеи.
- Сократить план до количества подтверждённых идей. До запуска Planner интерфейс
  показывает пересчитанные слоты из настроек именно этой недели. Общие настройки,
  исходный поиск и оплаченные ответы сохраняются.

Резерв — локальный предел допуска очередного запроса, а не гарантированная цена
AITUNNEL. Фактическая стоимость записывается в рублях. Превышение резерва, неизвестная
стоимость, исчерпание бюджета/числа запросов или неопределённый ответ блокируют
дальнейшие автоматические поиски. Для дозаполнения отключены даже повторы HTTP 429.
Если ошибка требует нового платного ответа, сначала нужна ручная проверка квитанции;
обычное «Продолжить» не снимает защиту. При неизвестной стоимости не следует выдавать
новое разрешение до сверки расходов. Готовые ответы повторно обрабатываются бесплатно.

Research, Writer, Image и QA учитываются по статье и версии входных данных в
`pipeline_items`. Ошибка одной статьи оставляет остальные в работе вплоть до QA.
Writer не запускается без достаточного актуального Research, Image — без готового
Writer. Локальные проверки текста, источников, изображений, расписания и дубликатов
продолжают действовать. Итоговое утверждение недели недоступно, пока не готовы все
заказанные статьи. В «Готовности отдельных статей» показаны статусы и причины ошибок;
в восстановлении можно выбрать конкретную проблемную статью для разрешения нового
ответа. Обычное продолжение использует успешные квитанции и готовые файлы без повторной
генерации; успешные статьи не пересоздаются.

Миграция SQLite 4 → 5 добавляет четыре таблицы учёта, предварительно создавая локальную
резервную копию в `data/backups`. Существующие строки, авторские промпты, импорты,
AI-квитанции и расходы не переписываются. Публикация и платные вызовы не выполняются
при миграции или простом открытии интерфейса.

Проверки разработки используют mock HTTP и отдельные SQLite-базы. Это подтверждает
техническое поведение, но не гарантирует качество новых тем реального Sonar.

Проверка 18.10.2026: весь pytest — 240 успешных тестов; Ruff и импорты — без ошибок;
23 сценария в Chromium с mock HTTP, включая согласие на дозаполнение, переход к
Planner, сокращение плана и независимую обработку статей. Streamlit перезапущен и
проверен на рабочей базе без запуска AI. Все прежние строки сверены с резервной
копией миграции; расходы запуска №2 остались 6 ₽. Реальных AI-запросов и публикаций
при этой доработке не выполнялось.
