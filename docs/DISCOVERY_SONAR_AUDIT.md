# Discovery / Sonar: HTTP 400

Проверено 18 октября 2026 года без реальных платных запросов.

## Что удалось установить

В запуске №1 ANALYZE уже SUCCEEDED. Неудавшийся вызов — `run:1:discovery`, модель
`sonar`, выбранная через fallback из пустого discovery_model в research_model.

Старый лог `error-3f0a48080e414aaf86bee083c55a6f2f.log` содержит HTTPStatusError 400,
но не тело ответа. В ai_calls оно также отсутствует. Исходящий JSON тогда не сохранялся.
**Точную причину именно исторического отказа по ответу API подтвердить невозможно.**
Нельзя выдавать текст mock-ошибки или восстановленный запрос за полученный от API ответ.

Запрос восстановлен локально из сохранённых настроек, промптов и результата Analytics:

| Параметр | До исправления | После |
| --- | --- | --- |
| Метод и адрес | POST https://api.aitunnel.ru/v1/chat/completions | Без изменения |
| model | sonar | Без изменения |
| messages | system + user; 42 626 и 10 622 символа | Содержимое без изменения |
| max_tokens | 16 000 | Без изменения, с прежним ограничением каталогом модели |
| response_format | `{"type":"json_object"}` | `json_schema` с исходной Pydantic-схемой DiscoveryV1 |
| tools, max_tool_calls, reasoning | Отсутствуют | Отсутствуют |

Обнаружена конкретная несовместимость: [актуальная спецификация Perplexity](https://docs.perplexity.ai/openapi.json)
для ApiChatCompletionsRequest допускает в response_format только text, json_schema или null;
json_object отсутствует в discriminator. Та же спецификация допускает роли system/user и
положительный max_tokens до 128 000. Использованный лимит 16 000 допустим также по
[странице Sonar AITUNNEL](https://aitunnel.ru/models/sonar).

[Документация AITUNNEL по JSON Schema](https://aitunnel.ru/docs/structured-outputs)
описывает response_format.json_schema.schema/name/strict и предупреждает, что поддержка
зависит от модели/провайдера. Поэтому исправление совместимости подтверждено спецификацией
и mock HTTP; успешный живой маршрут Sonar через AITUNNEL пока не проверен.

## Исправления

- Для Sonar и поддерживаемых вариантов Sonar, включая `perplexity/sonar`, structured-вызов
  отправляет json_schema с name, strict=true и неизменённым schema.model_json_schema().
- Активный промпт Discovery, история его версий и авторский контракт 1.0 не меняются.
  После ответа остаются Pydantic-валидация, проверка run_id, planning_window и источников.
- HTTP-ошибка теперь сохраняет очищенные параметры фактически отправленного запроса,
  тело ответа и x-request-id в локальный лог и ai_calls.result_json.http_error.
  Тело ограничено 32 768 символами после очистки; обрезание явно обозначается.
- Заголовки авторизации не записываются. Из вложенных полей и текстовых ошибок удаляются
  ключи API, Bearer/Basic, пароли, секреты, токены и cookies. Диагностика остаётся локальной.
- Для HTTP 400 интерфейс получает конкретное error.message. Сведения usage из тела
  HTTP-ошибки также учитываются; отсутствие стоимости не объявляется нулевой стоимостью.
- Повтор существующего ERROR блокируется до явного разрешения, в том числе для старого
  HTTP 400 без тела. Успешные ответы берутся из сохранённых квитанций, UNCERTAIN/PENDING
  остаются заблокированы. Прежняя политика настроенных повторов 429 сохранена.
  Нет автоматического перебора форматов ответа или запасных моделей.

Форма error.message/metadata.raw сверена с
[документацией ошибок AITUNNEL](https://aitunnel.ru/docs/errors).

На отдельной копии реальной SQLite запуск №1 возобновлён с Discovery и сохранён
валидный mock-результат. Analytics и его успешная стадия не менялись и не вызывались.

что прочие поля этих таблиц и все остальные таблицы не менялись. Последующие проверки
рабочую БД не изменяли. Миграция не требуется; расходы и оплаченные ответы не удалялись.

## Как продолжить

Когда пользователь готов к платному продолжению: открыть **Автопилот → запуск №1** и
нажать **«Продолжить подготовку»**. Разрешение именно этого повтора Discovery уже сохранено;
повторное архивирование не нужно. COLLECT_STATS и ANALYZE имеют SUCCEEDED и пропускаются.
Продолжение начнётся с Discovery, затем выполняется обычный pipeline, включая платный
Planner до проверки плана редактором.

Если в другом запуске ещё есть активная квитанция ERROR, сначала выбрать именно
`run:<id>:discovery` в восстановлении, сверить историю, отметить явное разрешение оплаты
и нажать «Разрешить повтор выбранного запроса». Изменение промптов, новый запуск недели
или повтор Analytics для этого исправления не нужны.
