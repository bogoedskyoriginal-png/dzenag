# Dzen Agent

Локальное приложение для подготовки статей в Яндекс Дзене. Откройте **http://localhost:8501**.

## Запуск и остановка

Дважды щёлкните **start.cmd** в папке проекта. Откроется браузер с приложением.
Для остановки интерфейса дважды щёлкните **stop.cmd**.
Фоновая подготовка недели и расписание управляются отдельно: сначала нажмите
красную кнопку **«Остановить автопилот»**, если хотите остановить всю работу агента.

Если удобнее терминал PowerShell, из папки проекта:

```powershell
.\.venv\Scripts\python.exe -m streamlit run dzen_agent/ui.py --server.address=127.0.0.1 --server.port=8501
```

При таком запуске остановка — Ctrl+C в том же терминале.

## Ключ AITUNNEL

Откройте файл `.env` в папке проекта обычным Блокнотом. В строке
`AITUNNEL_API_KEY=` вставьте свой ключ после знака равенства и сохраните файл.
Ключ не нужно отправлять в чат или вводить в интерфейс приложения.
Затем на **Главной** нажмите **«Обновить баланс»**. Перезапуск для нового ключа не требуется.

Ключ читается только из `.env`. Он не записывается в SQLite и не показывается в UI.
Старые OPENAI-настройки и прежние статьи сохранены; новый интерфейс использует AITUNNEL.
Без ключа доступны просмотр, ручное редактирование, импорт CSV и настройки.

## Первый порядок работы

1. **Настройки / Модели** → «Обновить каталог моделей». Это бесплатно, ключ не нужен.
   Если модели ещё не выбраны, приложение предложит недорогие варианты из актуального каталога.
   Выберите модели для Analytics, Discovery, Research, Planner, Writer и Image.
   Если отдельная модель Discovery не выбрана, используется модель Research.
   Sonar имеет собственный поиск. Для другой research-модели включите инструмент web search.
2. В этом же разделе задайте тематику канала, число статей, дни и время публикаций.
   Время в приложении — московское. Поддерживаются 1–21 статья, общие или отдельные
   слоты по дням. Для 21 статьи: все 7 дней, слоты `05:00, 06:00, 16:00`, максимум 3 в день.
   Лимит выходных токенов для подробного плана такого размера установите 42000 или выше
   (например 64000). При недостаточном лимите запрос остановится до оплаты.
   По умолчанию: 5 статей, до 2 исследований на статью,
   1 повтор после ограничения частоты, мягкий бюджет 200 ₽ за 30 дней.
3. **Промпты** → выберите назначение и вставьте ваш текст → «Сохранить новую версию».
   Авторские инструкции сохраняются дословно; для остальных ролей доступны стартовые шаблоны.
   Discovery требует отдельно согласованного промпта: приложение не создаёт его автоматически.
   Старые версии остаются в истории и восстанавливаются
   отдельной кнопкой как новая версия. Текст не переписывается автоматически.
4. **Статистика** → загрузите выгрузку CSV из кабинета Дзена. Посмотрите предпросмотр,
   при необходимости сопоставьте колонки и нажмите «Сохранить импорт».
   Укажите известный период измерения: неизвестные даты и метрики остаются неизвестными.
   Можно отдельно нажать «Проанализировать статистику» — это платный AI-запрос.
5. **Главная** → посмотрите количество ожидаемых операций → **«Подготовить неделю»**.
   Агент выполнит Analytics, поиск кандидатов Discovery и Planner, затем в REVIEW/MANUAL
   остановится для утверждения идей. Глубокий Research начнётся после утверждения.
   Состояние видно в разделе **Автопилот**.
6. **Контент-план** → посмотрите концепции и даты слева, обсудите идеи в блоке **«Груминг»** справа.
   Чат предложит изменения; только кнопка **«Применить»** меняет концепт. Ненужный вариант
   можно отклонить. До применения вы видите, что именно изменится.
7. Нажмите **«Утвердить контент-план и продолжить»**. Агент выполнит Research для выбранных
   концептов, затем создаст статьи, обложки и проведёт QA.
8. **Статьи** → откройте готовые материалы, при необходимости исправьте их.
   **Контент-план** или **Автопилот** → **«Утвердить неделю»**.
   Изменение текста, изображения или времени после утверждения требует новой проверки.

Если готовых источников мало, тема получает `insufficient_research`: приложение
останавливается, а не пишет неподтверждённый материал.

## Груминг контент-плана

В выбранной неделе слева находятся карточки идей, справа — редакторский чат.
Например: «Давай меньше военной темы», «Предложи пять вариантов вместо второй идеи»,
«Какие темы похожи на предыдущие публикации?» или «Поменяй местами третью и пятую публикации».
Редактор видит компактный контекст этой недели: концепты, аналитику, исследования,
недавние темы канала и его описание. История хранится отдельно для каждой недели.

**Editorial Chat использует модель Planner**, выбранную в настройках. Отдельной модели чата нет.
**Свежий Research использует Research model и Research prompt**, сохранённые для запуска.
Сам чат не вызывает интернет-поиск и не запускает Research или Writer.
Его вызовы оплачиваются как обычные запросы AITUNNEL, учитываются в бюджете и видны
в разделе **Расходы** как `EDITOR_CHAT`, с привязкой к запуску недели.

**Чат сам ничего не меняет без кнопки «Применить».** Предложение содержит причину и сравнение
старого и нового варианта. Можно применить одну правку или отклонить её.
Перестановку дат двух концептов применяйте кнопкой **«Применить все предложения вместе»**:
это позволяет безопасно обменять слоты. Перенос за пределы недели и конфликт времени запрещены.
Если концепт уже изменился после ответа AI, старое предложение нельзя применить поверх новой версии.

Замена темы или изменение ракурса помечает концепт для нового исследования.
После первого утверждения нового плана исследуются все выбранные концепты; при дальнейших
правках повторно исследуются только изменённые концепты. Изменение одного заголовка
или времени публикации не вызывает новый Research. Успешные платные этапы и готовые
исследования повторно не выполняются при обычном продолжении запуска.

Промпт редактора редактируется в **Промпты → Editorial Chat / Груминг**.
Новая версия и восстановление из истории работают так же, как для других промптов.

Две контрольные точки независимы:

```text
COLLECT_STATS → ANALYZE → DISCOVERY → PLAN → PLAN_REVIEW
→ RESEARCH → REFRESH_RESEARCH → WRITE → IMAGE → QA → REVIEW → DZEN_SCHEDULE → VERIFY
```

**PLAN_REVIEW** — разрешение создавать статьи по идеям. **REVIEW** — отдельное утверждение
готовых материалов после QA. Авторские контракты 1.0 требуют ручного утверждения концептов
и в AUTOPILOT. Старые запуски со стартовыми промптами сохраняют прежнее поведение режима.
Если изменить план после его утверждения, но до начала WRITE, потребуется утвердить его снова.
После начала WRITE груминг остаётся доступен для обсуждения, а правки готового текста выполняются
в разделе **Статьи**. Это защищает уже созданные материалы от рассинхронизации с концептами.

Старые БД автоматически обновляются до схемы 4 с локальной резервной копией.
Ранее созданные запуски сохраняют прежний порядок: Research перед Planner.
Готовые результаты не требуют повторной генерации.

## Analytics 1.0

Поддерживается полный JSON-контракт активного Analytics v3: качество данных, диагноз,
воронка, наблюдения, интерпретации, кластеры, эксперименты и два отдельных brief.
`discovery_brief` передаётся Discovery, `planner_brief` — Planner. Авторские промпты
при обновлении приложения не переписываются.

Старые результаты аналитики читаются в исходном формате. Статус `insufficient_data`
останавливает подготовку до платного поиска. После исправления импорта можно явно
подтвердить повтор аналитики в разделе восстановления, пока план ещё не создан.
История результатов и расходов сохраняется. Подробности —
[контракт и совместимость](docs/ANALYTICS_CONTRACT.md).

## Обложки и редактирование

В **Статьях** можно сохранить свой черновик, редактировать текст, перегенерировать
материал целиком, только заголовок или только текст. История изменений сохраняется.

При активном Image 1.0 кнопка **«Подобрать фото и собрать оформление»** использует
поисковую модель с просмотром изображений (Visual model; по умолчанию Research model).
Она ищет подлинные фотографии, затем просматривает скачанные файлы и выбирает размещение.
Поиск и просмотр — отдельные платные AI-вызовы. Обложка 1600×900 собирается локально:
фотография сохраняется целиком, текст помещается на плашке. Новые лица и сцены не генерируются.
Старый Image model для генерации остаётся доступен для прежних стартовых промптов.

В **«Готовая статья с иллюстрациями»** доступен просмотр сборки; сведения об источниках,
правообладателях и ограничениях находятся отдельно от текста статьи. Неопределённые права
не останавливают подбор; явно ограниченные источники не используются. Недоступные сайты
и неподтверждённые кадры не подменяются вымышленными. За проход проверяется до 12 фотографий.
Без проверенной основы для обложки материал остаётся на редакционной проверке.

«Загрузить свою картинку» → «Использовать мою картинку» заменяет активную обложку.
Изображения находятся в `data/images/<номер статьи>/`. Предыдущие файлы сохраняются.
После ручного изменения текста визуальную сборку нужно обновить. QA проверяет, что
сборка не потеряла текст, ссылки на факты действительны, файлы целы и обложка имеет формат 16:9.

## Дзен и первый вход

**Автопилот** → **«Открыть браузер Дзена для входа / диагностики»**.
В отдельном Chromium нажмите «Войти» и авторизуйтесь сами. CAPTCHA и 2FA также выполняете вы.
Профиль сохраняется в `browser-profile/`. После обычного входа закройте это окно
перед следующей операцией: один профиль нельзя одновременно открыть дважды.

Старый адрес редактора V0 оказался недействительным. После проверки адреса редактора
вашего канала его можно сохранить в **Настройки / Модели**.
Кнопка **«Подготовить в Дзене»** сохраняет сценарий V0: заполнение заголовка и текста.

**Автоматическое создание отложенных публикаций, загрузка обложек в Дзен и обновление
отложенной статьи пока ожидают реализации и проверки на вашем авторизованном канале.**
Кнопки отправки сейчас сообщают об этой зависимости. Статус успешной публикации
не выставляется без проверки. Тестовых публикаций пока не создано.
Автоматическая выгрузка CSV также пока использует ручной импорт как основной путь.

При изменении интерфейса Дзена не запускайте повтор вслепую. Откройте диагностику
и передайте разработчику описание ошибки. Локальные снимки и журнал находятся в
`data/browser-diagnostics/` и `logs/`; они могут содержать приватную информацию и не входят в Git.

## REVIEW, MANUAL и AUTOPILOT

В **Автопилоте** выберите режим и нажмите «Применить режим»:

- **REVIEW** (по умолчанию): сначала ждёт утверждения идей, затем готовит материалы
  и ждёт отдельного «Утвердить неделю».
- **MANUAL**: также ждёт утверждения контент-плана; действия в Дзене запускаются отдельными кнопками.
- **AUTOPILOT**: требует явной галочки-разрешения на автономную работу.
  Пока живой адаптер Дзена не проверен, цикл остановится перед отправкой.

Большая красная кнопка **«Остановить автопилот»** находится слева во всех разделах.
Она запрещает следующие операции и выключает запуск по расписанию в приложении.
Уже отправленный AI-запрос может завершиться и быть оплачен; сохранённые результаты не удаляются.
Для продолжения: **Автопилот** → «Возобновить работу агента» → выберите запуск → «Продолжить подготовку».

## Расписание Windows

В **Автопилоте** задайте день и время и нажмите «Установить / обновить расписание».
Приложение создаст отдельное задание Windows. Браузер и Streamlit можно закрыть.
Компьютер должен быть включён, а вы должны войти в Windows. Пропущенный запуск
может выполниться после включения компьютера. Один и тот же недельный запуск не дублируется.

«Проверить задание Windows» показывает реальное состояние задания.
«Выключить расписание» отключает его в приложении и удаляет задание Windows.
По умолчанию расписание выключено; установка зависимостей его не включает.

Для технической диагностики предусмотрены `scripts/install_scheduler.ps1`,
`scripts/remove_scheduler.ps1` и независимый CLI:

```powershell
.\.venv\Scripts\python.exe -m dzen_agent.pipeline.run
```

## Расходы и восстановление после ошибок

**Главная** показывает точный баланс аккаунта, бюджет ключа и сводку текущего ключа
из AITUNNEL. Сводка сервиса может обновляться с задержкой около часа.
**Расходы** показывает локальные вызовы, стоимость по статьям и запускам, сегодня и за 30 дней.
Все суммы — в рублях. Если API не вернул стоимость, она отмечается неизвестной.

Общие Analytics/Planner учитываются в стоимости запуска. Перед каждым новым AI-вызовом
проверяются локальный бюджет и минимальный баланс. Мягкий лимит не является банковским
ограничением: один запрос может пересечь его. Жёсткий бюджет можно задать на ключе AITUNNEL.

При ошибке нажмите «Продолжить подготовку»: готовые этапы, статьи и картинки используются повторно.
После сетевого timeout/5xx оплата может быть неизвестной, поэтому автоматический повтор запрещён.
Проверьте историю AITUNNEL, затем в **Автопилот → Восстановление после ошибки AI**
при необходимости разрешите новый платный запрос. Там же можно применить новые модели
и промпты к незавершённым этапам. Изменения не переписывают уже готовые статьи.
Технические подробности сохраняются в `logs/`; интерфейс показывает понятное сообщение.

## Данные и обновления

Статьи и настройки: `data/dzen_agent.db`. Перед изменением схемы создаётся SQLite-копия
в `data/backups/`. Миграции добавляют таблицы и поля, сохраняя V0 и прежние статусы.
Не удаляйте папки `data` и `browser-profile`, если хотите сохранить материалы и вход.
`.env`, базы, изображения, браузерный профиль и журналы исключены из Git.

## Установка с нуля и проверки для разработчика

Нужен Python 3.11+; рабочее окружение уже настроено в `.venv`.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD\.playwright"
.\.venv\Scripts\python.exe -m playwright install chromium
Copy-Item .env.example .env  # Только если .env ещё не существует
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m ruff check .
```

Проверки AI выполняются на mock-ответах и не расходуют деньги. Реальное состояние
интеграций и оставшиеся задачи описаны в [docs/IMPLEMENTATION_STATUS.md](docs/IMPLEMENTATION_STATUS.md).
Аудит авторских контрактов и подготовка первого платного теста —
[docs/READINESS_AUDIT.md](docs/READINESS_AUDIT.md).
